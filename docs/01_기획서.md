# Re:Work 기획서

| 항목 | 내용 |
|---|---|
| **서비스** | 반복 보고 업무의 계산 규칙과 판단 근거를 되찾아 인수인계하는 B2B AI Agent |
| **대상** | 매월 보고서를 작성하고, 담당자가 바뀔 때 업무 설명에 어려움을 겪는 기업 운영팀 |
| **초기 도메인** | 점포 월간 판매 실적 보고서 (원천 판매 데이터 CSV + 완성 보고서 PDF) |
| **산출물** | 인수인계 매뉴얼, 재실행 가능한 업무 규칙, 검증 결과, 다음 기간 보고서 초안 |

---

## 1. 기획 배경

매월 보고서는 남지만, 그 결과를 만든 선택은 보고서에 다 담기지 않는다. 어떤 열을 어떻게 합쳤는지, 어떤 기간을 기준으로 비교했는지, 왜 특정 품목의 발주를 줄이자고 했는지는 담당자의 머릿속이나 메신저, 개인 메모에 흩어진다.

담당자가 바뀌면 후임자는 같은 숫자를 다시 만들기 위해 계산을 거꾸로 추적하고, 숫자를 맞춘 뒤에도 그 숫자로 어떤 판단을 내렸는지 설명하기 어렵다. 파일을 넘겨주는 것만으로는 이 공백이 메워지지 않는다.

Re:Work는 이미 남아 있는 **완성 보고서와 원천 데이터**에서 출발한다. 보고서의 숫자를 만든 계산 규칙을 찾아 원천 데이터로 다시 계산해 검증하고, 보고서의 제안이 어떤 데이터에 근거했는지 조사한다. 데이터로 설명되지 않는 부분만 담당자에게 묻는다. 결과는 후임자가 읽는 매뉴얼과, 다음 달 데이터에 그대로 다시 적용할 수 있는 규칙으로 남는다.

## 2. 문제: 보고서에 남지 않는 것

| 업무 순간 | 사라지는 정보 | Re:Work가 남기는 것 |
|---|---|---|
| 숫자를 만든 순간 | 집계 열·연산·단위·반올림·기간 | 원천 데이터로 다시 계산해 검증한 계산 규칙 |
| 제안을 정한 순간 | 어떤 추세·비교·기준을 보고 판단했는가 | 결정별 근거 데이터와 재사용 가능한 판단 기준 |
| 데이터 밖의 판단 | 현장 상황, 본사 지시, 경험 | 담당자 답변과 확인 이력 |
| 다음 달 재작성 | 지난달 기준을 그대로 써도 되는가 | 데이터 구조 검사와 규칙 재적용 결과 |

## 3. 해결 방안

### 3.1 두 층의 복원

| 층 | 질문 | 방법 |
|---|---|---|
| **1층 계산 규칙** | 보고서의 이 숫자는 어떤 계산으로 나왔는가 | 모델이 규칙 후보(열·연산·단위·반올림)를 제안하고, 계산 도구가 원천 데이터로 다시 계산해 보고서 값과 칸별로 대조한다 |
| **2층 판단 근거** | 왜 이 품목은 늘리고 저 품목은 줄였는가 | 모델이 분석 도구(추세·기준선·행사 효과·요일·순위)를 골라 근거를 찾고, 코드가 인용한 숫자와 비교 대상을 검사한다 |

숫자가 맞는다고 판단의 이유까지 증명되는 것은 아니므로 두 층의 결과를 따로 기록한다.

### 3.2 업무 흐름

| 단계 | 사용자가 얻는 것 | 시스템이 하는 일 |
|---|---|---|
| A. 입력 준비 | 분석 범위가 명확해진다 | CSV 구조와 PDF의 표·제안을 읽고, 관련 업무 규정을 검색한다 |
| B. 계산 규칙 복원 | 검증된 계산 방법 | 규칙 제안 → 실제 계산 → 보고서 값과 대조 (최대 3회) |
| C. 판단 근거 조사 | 출처가 연결된 판단 이유 | 제안을 결정 단위로 나누고, 결정마다 도구로 근거를 조사·판정한다 |
| D. 담당자 확인 | 데이터 밖의 기준이 기록된다 | 설명되지 않는 결정만 객관식으로 묻는다. 지금 답하거나 나중에 답할 수 있다 |
| E. 결과물·재사용 | 후임자가 읽고 다시 실행할 자료 | 매뉴얼·규칙·검증 결과를 만들고, 다음 기간 데이터에 규칙을 다시 적용한다 |

### 3.3 설계 원칙

- **숫자는 모델이 아니라 계산 도구가 만든다.** 모델은 가설과 도구 선택만 하고, 집계는 MCP 서버의 허용된 연산으로 한다.
- **"데이터로 설명됨"과 "담당자가 확인함"을 구분한다.** 매뉴얼의 모든 판단에 확인됨 / 추정 / 모름 / 반려 라벨을 붙여, 후임자가 어디까지 믿을지 알 수 있게 한다.
- **모르는 것은 지어내지 않는다.** 근거가 부족하면 질문하거나 미해결로 남긴다.
- **담당자의 부담을 줄인다.** 데이터로 설명된 결정은 묻지 않고, 설명되지 않는 결정만 한 번에 최대 3개 묻는다.

## 4. 사용자 이용 흐름

**전임 담당자**
1. 원천 CSV와 완성 보고서 PDF를 한 번에 끌어다 놓고 분석을 시작한다.
2. 진행 화면에서 단계(입력 준비 → 계산 규칙 → 판단 근거 → 담당자 확인 → 결과물)와 이벤트를 본다.
3. 데이터로 설명되지 않는 결정에 대한 객관식 질문에 답한다. 바로 답하기 어려우면 "나중에 답하기"를 누르고, 완료 후에 답해도 매뉴얼이 갱신된다.

**후임 담당자**
1. 계산 규칙 탭에서 지표마다 업무 언어 설명과 엑셀 수식을 본다.
2. 판단 근거 탭과 매뉴얼에서 결정별 근거와 확인 상태를 읽는다.
3. 다음 달 데이터를 올려 저장된 규칙으로 보고서 초안을 만든다. 열 이름이나 값이 바뀌었으면 임의로 처리하지 않고 알려 준다.

## 5. 이해관계자

| 이해관계자 | 현재의 어려움 | Re:Work가 주는 가치 |
|---|---|---|
| 전임 담당자 | 암묵적인 계산과 예외를 모두 문서로 쓰기 어렵다 | 필요한 질문에만 답하면 규칙과 판단이 정리된다 |
| 후임 담당자 | 이전 보고서의 계산과 이유를 재현하기 어렵다 | 규칙·근거·확인 상태를 보고 같은 보고서를 다시 만든다 |
| 팀장·관리자 | 보고 품질과 인수인계 누락을 판단하기 어렵다 | 항목별 근거와 미해결 사항을 한눈에 검토한다 |
| 운영 조직 | 보고 업무가 개인에게 의존한다 | 업무별 규칙이 자산으로 쌓이고 재사용된다 |
| 시스템 관리자 | 접근·장애·비용을 통제해야 한다 | 회사별 격리, 실행 추적, 토큰·비용 기록, 자동 재시도 |

## 6. 비즈니스 가치와 차별성

### 6.1 기존 방식과의 차이

| 방식 | 주로 해결하는 일 | Re:Work가 더하는 것 |
|---|---|---|
| 수작업 매뉴얼 | 사람이 절차와 예외를 정리 | 자료에서 규칙을 찾아 검증하고, 확인할 항목만 묻는다 |
| RPA | 정의된 절차의 반복 실행 | 기존 결과에서 규칙 자체를 찾아낸다 |
| 범용 LLM 대화 | 요약·질의응답·초안 | 계산 검증, 근거 ID, 확인 상태, 재실행을 관리한다 |
| BI·리포팅 | 정의된 지표의 집계·시각화 | 지표 정의와 판단 이유를 함께 넘겨준다 |

Re:Work는 기존 BI·RPA·문서 관리를 대체하지 않는다. 보고서의 계산 규칙과 판단 근거를 확인하고 넘겨주는 구간을 연결한다.

### 6.2 사업화 방향

| 단계 | 제공물 | 과금 방식 |
|---|---|---|
| 도입 진단 | 대상 업무 선정, 기준 데이터 연결, 검증 보고 | 범위와 투입 인력 기준 산정 |
| 운영 전환 | 업무 템플릿, 권한, 운영 지원 | 기본 이용료 + 업무 단위 사용량 |
| 확장 | 추가 업무 도메인, 내부 시스템 연계 | 연계 개발·운영 별도 산정 |

도입 효과는 **월 보고 횟수 × 건당 절감 시간 × 적용 인원 × 내부 시간 단가**에서 운영·검토 비용을 뺀 값으로 산정하고, 인수인계 기간과 재작업 건수를 함께 본다.

## 7. 서비스 범위

### 7.1 포함 범위

- 원천 판매 데이터 CSV와 완성 보고서 PDF 입력
- 보고서 표의 계산 규칙 복원과 수치 검증 (표 6개, 검증 지표 16개)
- 보고서 제안의 판단 근거 조사 (제안 5개, 분석 도구 5종)
- 담당자 질문·답변, 완료 후 답변 반영
- 인수인계 매뉴얼, 업무 규칙 JSON, 검증 결과 CSV
- 다음 기간 데이터에 규칙을 재적용한 보고서 초안 (모델 호출 없음)
- 회사별 데이터 격리, 실행 추적, 장애 자동 복구

### 7.2 범위 밖

- 전사 문서 전체의 자동 이해
- ERP 등 업무 시스템의 거래 처리
- 담당자 확인 없는 판단의 자동 확정

## 8. 결과물

| 결과물 | 내용 |
|---|---|
| 인수인계 매뉴얼 (Markdown) | 보고서 개요, 매달 만드는 순서, 판단 규칙(라벨 + 접을 수 있는 근거), 계산 규칙, 원천 데이터 열, 확인 필요 사항 |
| 업무 규칙 (JSON) | 지표별 계산 규칙과 판단 기준. 다음 기간 재실행에 쓴다 |
| 검증 결과 (CSV) | 보고서 값과 다시 계산한 값의 칸별 비교 |
| 다음 기간 보고서 초안 (CSV · Markdown) | 저장된 규칙을 새 기간 데이터에 적용한 결과 |
