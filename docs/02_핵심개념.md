# Re:Work 핵심 개념: 보고서 속 "판단 근거"를 되찾는다

## 1. 한 줄 요약

> 완성된 보고서의 **제안**과 **원천 데이터**를 함께 넣으면, Re:Work는 담당자가 그 제안을 하기까지 **어떤 데이터를, 어느 기간에 걸쳐, 어떤 기준으로 봤는지** 추론해서 인수인계 매뉴얼로 남긴다.

## 2. 왜 필요한가

월간 보고서에는 숫자만 있지 않다. 담당자의 의견과 다음 달 제안이 함께 들어간다.

> "음료 수요가 봄부터 꾸준히 오르고 있어 7월 메인을 음료로 잡겠습니다."
> "단팥빵은 몇 달째 계속 줄고 있어 발주를 1단위 줄이겠습니다."

하지만 보고서에는 **결론과 짧은 근거 한마디**만 남는다. 담당자가 실제로 확인한 숫자는 보고서에 적히지 않는다. 예를 들면 몇 달간의 추세, 행사한 날과 안 한 날의 비교, 요일별 판매량 같은 것들이다.

담당자가 바뀌면 후임자는 보고서만 보고 이렇게 묻게 된다.

- "음료가 꾸준히 올랐다"는 몇 달을 기준으로 본 걸까?
- "할인해도 안 늘었다"는 무엇과 무엇을 비교한 걸까?
- 전월 대비 감소 폭은 카스텔라가 더 큰데, 왜 단팥빵만 줄였을까?

**보고서는 남아도 판단 방법은 사라진다.** Re:Work는 이 사라진 판단 방법을 원천 데이터에서 되찾는다.

## 3. 시연 예시: ST001 점포 2026년 6월 판매 실적 보고서

- **입력 1 (완성 보고서):** `reports/2026-06_ST001_월간판매실적보고서.pdf`
  - 1~7장: 5월과 6월을 비교한 실적 수치
  - 8장: 담당자의 7월 판매 기획 제안
- **입력 2 (원천 데이터):** `data/판매분석가_일별상세.csv`
  - 2026-01-24 ~ 2026-07-22, 36개 품목의 일별 판매 기록

보고서에는 **5월과 6월 비교만** 있다. 하지만 담당자는 **2~6월 추세와 행사일 데이터**를 보고 판단했다. 이 차이를 Re:Work가 찾아내야 한다.

### 보고서의 제안과 원천 데이터의 숨은 근거

| 보고서의 제안 (적힌 근거) | 원천 데이터에 있는 숨은 근거 | 판단 유형 |
|---|---|---|
| ① 음료를 메인으로, 제로콜라·에너지드링크 발주 20% 확대 ("봄부터 꾸준히") | 일평균 판매수량 2~6월 추세. 제로콜라 8.7 → 12.3으로 **2→6월 매달 증가 (4개월 연속 증가)**, 에너지드링크 6.2 → 8.3으로 6월 급증 | 장기 추세 |
| ② 제육볶음 도시락은 행사에서 빼고 정가 판매 ("할인해도 크게 안 늘어서") | 행사일 10.3개 vs 비행사일 10.0개, **행사 효과 +3%** | 행사 효과 |
| ② 금요일 도시락 입고 확대 ("금요일에 많이 나가서") | 요일별 도시락 일평균 수량: **금요일 32.2개**, 다른 요일은 16~26개 | 요일 패턴 |
| ③ 초코바·감자칩 행사 유지, 단팥빵·초코우유 제외 | 행사일과 비행사일의 일평균 수량 차이: 초코바 **+155%**, 감자칩 +82%, 단팥빵 **−26%**, 초코우유 −8% | 행사 효과 |
| ④ 카스텔라·크림빵 발주 유지 ("5월이 유난히 많이 팔린 달") | 2~4월 평소 수준(약 3.3, 약 5.0)보다 5월이 튀었음. 6월 감소는 **평소 수준으로 돌아온 것** | 기준선 비교 |
| ④ 단팥빵 발주 축소 ("몇 달째 계속 줄어서") | 6.7 → 6.5 → 6.1 → 5.3, **3개월 연속 감소** | 장기 추세 |
| ⑤ 참치캔 점검 ("두 달 연속 감소") | 3.9 → 3.2 → 2.6 | 장기 추세 |

※ 수치는 월별 일평균 판매수량(개/일)이다.

### 가장 좋은 시험 문제: ④ 베이커리

보고서의 전월 대비 표만 보면 이렇다.

| 품목 | 전월 대비 |
|---|---|
| 카스텔라 | −26.1% |
| 크림빵 | −24.2% |
| 단팥빵 | −17.1% |

표만 보면 카스텔라와 크림빵을 줄여야 할 것 같다. 하지만 담당자는 **두 품목은 유지하고 감소 폭이 더 작은 단팥빵을 줄였다.**

원천 데이터에서 몇 달치 기준선을 봐야만 이 판단을 설명할 수 있다.

```text
카스텔라  2월 3.3 → 3월 3.5 → 4월 2.8 → 5월 4.9(반짝) → 6월 3.8   ⇒ 평소 수준으로 복귀
단팥빵    2월 6.3 → 3월 6.7 → 4월 6.5 → 5월 6.1 → 6월 5.3          ⇒ 꾸준한 하락
```

보고서에 적힌 숫자만으로는 정답을 낼 수 없고, 원천 데이터를 직접 탐색해야 하는 문제다.

## 4. Re:Work가 추론하는 두 층

| 층 | 무엇을 찾는가 | 예시 | 결과물 |
|---|---|---|---|
| **1층: 계산 규칙** | 보고서 숫자를 원천 데이터로 똑같이 재현하는 방법 | 매출 = 할인 후 금액 합계, 천원 단위 반올림, 주말 = 토·일 | 업무 규칙 JSON, 다음 달 보고서 초안 |
| **2층: 판단 근거** | 제안마다 어떤 지표를, 어느 기간에 걸쳐, 어떤 기준으로 봤는가 | "발주는 전월 대비가 아니라 3개월 이상 추세로 판단", "행사 효과가 10% 미만이면 행사에서 제외" | 인수인계 매뉴얼의 "판단 기준" 장 |

1층은 **숫자가 맞는지**로 검증할 수 있다. 2층은 **여러 근거 후보 중 제안을 가장 잘 설명하는 것**을 찾고, 확실하지 않으면 담당자에게 묻는다.

## 5. Agent가 일하는 순서 (2층 기준)

```text
1. 보고서에서 제안 문장 추출
   "단팥빵은 몇 달째 계속 줄고 있어 발주를 1단위 줄이겠습니다."
        ↓
2. 제안의 대상·행동·적힌 근거 분해
   대상: 단팥빵 / 행동: 발주 축소 / 적힌 근거: "몇 달째 감소"
        ↓
3. 근거 후보를 세우고 계산 도구로 검증 (business-mcp)
   후보 A: 전월 대비 감소      → 카스텔라가 더 크게 감소했으므로 설명 불가 ✗
   후보 B: 3개월 연속 감소     → 단팥빵만 해당 ✓
   후보 C: 행사 효과 없음      → −26%로 해당 ✓ (보조 근거)
        ↓
4. 판단 기준으로 일반화
   "발주 축소는 3개월 연속 감소한 품목에 적용한다"
        ↓
5. 데이터로 설명이 안 되는 부분은 담당자에게 질문
   "쇼케이스 1칸 교체 결정에는 어떤 기준이 있었나요?"
        ↓
6. 인수인계 매뉴얼에 기록
   제안 · 근거 데이터 · 기간 · 기준 · 확인 여부
```

## 6. 결과물 예시: 인수인계 매뉴얼 "판단 기준" 장

```markdown
### 발주 축소 판단
- 기준: 전월 대비가 아니라 **최근 3개월 이상 일평균 판매수량 추세**를 본다.
- 한 달만 튄 경우(예: 2026년 5월 카스텔라)는 평소 수준으로 돌아온 것으로 보고 발주를 유지한다.
- 근거 데이터: 판매분석가_일별상세.csv / sales_quantity / 2026-02 ~ 2026-06
- 상태: 수치 검증 완료 (matched) · 담당자 확인 대기 (unconfirmed)

### 행사 품목 선정
- 기준: 같은 달 안에서 **행사일 일평균 판매수량 ÷ 비행사일 일평균 판매수량**을 비교한다.
- 효과가 거의 없거나(+3%) 오히려 줄어든(−26%) 품목은 다음 달 행사에서 뺀다.
- 정확한 기준값(예: 10%)은 데이터로 확정할 수 없음 → 담당자에게 질문
```

## 7. 기존 도구와의 차이

| | 일반 BI·대시보드 | 일반 LLM 요약 | **Re:Work** |
|---|---|---|---|
| 보고서 숫자 재현 | 사람이 직접 설정 | 계산 신뢰성 낮음 | 계산 도구로 검증 |
| 제안의 근거 설명 | 없음 | 그럴듯하게 지어낼 위험 | 원천 데이터로 검증된 근거만 채택 |
| 모르는 부분 처리 | 해당 없음 | 추측으로 채움 | 담당자에게 질문 후 기록 |
| 남는 것 | 차트 | 요약문 | 재실행 가능한 규칙 + 판단 기준 매뉴얼 |

## 8. 원칙

- **숫자는 모델이 아니라 계산 도구가 만든다.** 근거 후보는 모두 business-mcp로 실제 계산해 확인한다.
- **"수치로 설명됨"과 "담당자가 확인함"은 다르다.** 여러 근거가 같은 제안을 설명할 수 있으므로, 담당자가 확인하기 전까지는 추정으로 표시한다.
- **데이터로 설명되지 않는 제안은 지어내지 않는다.** 미확인 항목으로 남기고 질문한다.
- **정답표(이 문서 3장의 표)는 Agent 입력에 넣지 않는다.** 테스트할 때 정답 비교용으로만 쓴다.
